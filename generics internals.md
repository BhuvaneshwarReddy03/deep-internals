## What are generics, and why are they useful?
**Generics** (introduced in Java 5) enable types (classes and interfaces) to be parameters when defining classes, interfaces, and methods. They allow you to write reusable, type-safe code without hardcoding specific data types.

---

### Why Generics Are Useful (The 3 Core Benefits)

**1. Strong Compile-Time Type Safety**
Before Java 5, collections stored raw `Object` references. You could accidentally put an `Integer` into a list intended for strings:

```java
// Pre-Java 5 (Raw Types)
List list = new ArrayList();
list.add("Hello");
list.add(100); // Compiles without issues, but dangerous!

```

With generics, the compiler catches type mismatches immediately at build time, preventing runtime bugs:

```java
List<String> list = new ArrayList<>();
list.add("Hello");
// list.add(100); // Compile-time error!

```

**2. Elimination of Explicit Type Casting**
Without generics, retrieving items from a collection required explicit casting, which risked throwing `ClassCastException` at runtime:

```java
// Without Generics: Manual casting required
String s = (String) list.get(0); 

// With Generics: Automatic and guaranteed safe
String s = list.get(0);

```

**3. Code Reusability and Generic Algorithms**
A single generic class or method can work uniformly across different types without duplicating code:

```java
public <T> void swap(T[] array, int i, int j) {
    T temp = array[i];
    array[i] = array[j];
    array[j] = temp;
}

```

---

### Key Mechanism: Type Erasure

Interviewers almost always ask: *"How are generics implemented under the hood?"*

* **Type Erasure:** To maintain backward compatibility with pre-Java 5 code, the Java compiler uses type erasure.
* At compile time, the compiler inspects type parameters, enforces type safety, and inserts necessary casts.
* It then **erases/strips** all generic type parameters from the generated bytecode, replacing them with their bound (or `Object` if unbounded).
* At runtime, `List<String>` and `List<Integer>` are both just raw `List` instances in the JVM.

---
> 
> Under the hood, Java implements generics via **Type Erasure**, removing all generic type information during compilation to maintain backward compatibility with legacy bytecode."
